What T(n) represents

T(n) is the number of primitive operations an algorithm performs on an input of size n, counted with one fixed set of rules (the counting model below). It turns the structure of the code into a function you can reason about.

A model, not a stopwatch. "T(n) = 4n + 7" doesn't mean the CPU executes exactly 4n + 7 instructions - a compiler might emit 3 or 30 instructions for one assignment. It means "4n + 7 operations under this app's counting rules". Different textbooks use slightly different rules and get different constants; the growth (Θ) comes out the same.

Statement execution counts

Each row contributes cost × executions. A statement outside every loop runs once. A statement inside a loop runs once per iteration. T(n) is the sum over all rows:

T(n) = Σ (cost of row) × (times the row executes)

Loop initialization, comparisons and increments

Loops are written with all three parts visible: for (init; condition; update). If the body runs I times each time the loop is reached:

PartRunsWhy
i = 01once, before the first check
i < nI + 1once per iteration, plus the final check that fails and ends the loop
i++Iafter every iteration
bodyIonce per iteration

Worked example - sum an array:

procedure SumArray(A, n)
    sum = 0                      cost 1 × 1        = 1
    for (i = 0; i < n; i++)      i = 0:  1 × 1     = 1
                                 i < n:  1 × (n+1) = n + 1
                                 i++:    1 × n     = n
        sum = sum + A[i]         cost 2 × n        = 2n
    return sum                   cost 1 × 1        = 1
T(n) = 1 + 1 + (n + 1) + n + 2n + 1 = 4n + 4 → Θ(n)

Watch the bound: i <= n starting at 1 is also n iterations; i < n - 1 is n - 1 iterations and its check costs 2 (the subtraction); i < 2 * n is 2n iterations with a check of cost 2.

Sequential statements: add

Code that runs one block after another adds: derive each part, then T(n) = T₁(n) + T₂(n).

for (i = 0; i < n; i++)          T₁(n) = 1 + (n + 1) + n + n = 3n + 2
    print(A[i])
for (j = 0; j < n; j++)          T₂(n) = 3n + 2
    print(A[j])
T(n) = (3n + 2) + (3n + 2) = 6n + 4 - added, not multiplied: Θ(n)

Nested loops: the inner loop runs for every outer iteration

count = 0                                    1
for (i = 0; i < n; i++)                      i = 0: 1 · i < n: n + 1 · i++: n
    for (j = 0; j < n; j++)                  j = 0: n · j < n: n(n + 1) · j++: n²
        count = count + 1                    2 × n²
return count                                 1

The inner loop is reached n times, so its init runs n times, its condition (n + 1) times per visit = n(n + 1) in total, and its update and body n · n = n² times.

T(n) = 1 + 1 + (n + 1) + n + n + (n² + n) + n² + 2n² + 1 = 4n² + 4n + 4 → Θ(n²)

The classic slip is counting the inner loop n times in total instead of n times per outer iteration.

Summations

When the inner bound depends on the outer variable, the inner loop runs a different number of times on each outer iteration - add those counts instead of multiplying:

for (i = 0; i < n; i++)
    for (j = 0; j <= i; j++)      runs i + 1 times on outer iteration i
        count = count + 1
body executions = 1 + 2 + 3 + … + n = n(n + 1)/2 = n²/2 + n/2 inner checks = Σ (i + 2) = n²/2 + 3n/2 T(n) (with count = 0 and return count) = 2n² + 6n + 4 → Θ(n²)

Logarithmic loops

i = 1                       1
while (i < n)               log₂ n + 1
    i = i * 2               2 × log₂ n

i takes the values 1, 2, 4, …, 2ᵏ; the loop stops when 2ᵏ ≥ n, i.e. after k = log₂ n iterations (assuming n is a power of 2 so the count is a whole number). Halving (i = i / 2 down to 1) is the same count.

T(n) = 1 + (log₂ n + 1) + 2 log₂ n = 3 log₂ n + 2 → Θ(log n)

In this section log(n) means log₂ n. A linear loop around a doubling loop gives terms in n log₂ n.

Several input sizes

Keep independent sizes separate. An n-loop around an m-loop:

T(n, m) = 1 + 1 + (n + 1) + n + n + n(m + 1) + nm + 2nm + 1 = 4nm + 4n + 4 → Θ(nm)

Writing n² here would be wrong unless m = n. Sequential loops over n and m give Θ(n + m) - neither term can be dropped.

Input-dependent execution: best and worst case

With an if or an early return, the number of operations depends on the data, not only on n. There is then no single T(n) - each case has its own function:

for (i = 0; i < n; i++)
    if (A[i] == target)
        return i
return -1
best case (target is A[0]): 1 + 1 + 1 + 1 = 4 → Θ(1) worst case (target absent): 1 + (n + 1) + n + n + 1 = 3n + 3 → Θ(n)

Tbest(n) is the minimum count over all inputs of size n; Tworst(n) the maximum. Both are ordinary functions you can simplify and classify.

Simplifying T(n)

Expand products and collect like terms into one term per power: (n + 1) + n + 2n + 3 → 4n + 4; n(n + 1)/2 → n²/2 + n/2. Any equivalent form is accepted as an answer - 3n + 4, 4 + 3n, n + n + n + 4 all match - but the guided mode asks for the simplified form explicitly.

Growth order: 1 < log n < n < n log n < n² < n³. Keep the fastest-growing term (for several variables, every term not dominated by another, e.g. nm + k), then drop its constant factor. T(n) and Θ are related but different statements: T(n) is a specific function; Θ(n²) is the set of all functions that grow like n². See Learn → Big Θ for the formal definitions.
